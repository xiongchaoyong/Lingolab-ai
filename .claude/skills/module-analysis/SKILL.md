# 功能模块分析技能

## 描述

按照 `docs/功能模块分析文档工作流.md` 定义的三阶段工作流，对 PRD 中的功能模块进行完整的子功能拆解、用例图绘制、详细规格编写。

## 指令

当被调用时，执行以下步骤：

### 步骤 0：确认模块

如果用户未指定模块编号，询问要分析哪个模块。从 `docs/lingolab-ai-v1.0-prd.md` 中查找模块信息。

### 步骤 1：读取工作流文档

读取 `docs/功能模块分析文档工作流.md`，严格按照其中定义的三个阶段执行。

### 步骤 2：Git 分支准备

按照项目 CLAUDE.md 规范：
1. `git checkout dev` → `git pull origin dev` → `git pull origin main`
2. 创建分支：`git checkout -b docs/module-{编号}-analysis`

### 阶段 1：子功能拆解

参考 PRD 中对应模块的需求，将模块拆解为独立可开发、可测试的子功能，生成无序列表 `(1) (2) (3) ...` 格式，输出到：
`docs/功能模块需求分析/模块{编号}-{名称}/子功能清单.md`

### 阶段 2：用例图

使用 `/drawio-skill` 绘制 UML 用例图，描述角色与子功能的交互关系，保存到：
`docs/功能模块需求分析/模块{编号}-{名称}/用例图/drawio/模块{编号}-用例图.drawio`

### 阶段 3：详细规格说明 + 流程图

对每个子功能按模板编写需求描述、输入、处理、输出，全部写入：
`docs/功能模块需求分析/模块{编号}-{名称}/详细规格说明.md`

对涉及多步骤处理、条件分支的子功能，使用 `/drawio-skill` 生成流程图，保存到：
`docs/功能模块需求分析/模块{编号}-{名称}/流程图/drawio/`

### 步骤 3：更新 ai-log.md

完成后更新 `ai-log.md` 记录操作摘要。

## 行为准则

- 严格按照工作流文档的三阶段顺序执行
- 每个阶段完成后请用户审核再继续
- 子功能拆解粒度：一个子功能 = 一个独立可开发、可测试、可交付的最小单元
- 流程图主流程使用直线连接，分支使用正交路由
- 所有 drawio 文件同时导出 png
