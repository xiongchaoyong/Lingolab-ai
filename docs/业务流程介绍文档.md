# Lingolab 业务流程介绍文档

> 面向客户演示与产品介绍，按学习者、教师、运营三类角色介绍业务流程。

---

## 一、用户端 — 从测评定级到持续提升的完整学习流程

用户端是系统的核心，覆盖用户从零基础入门到持续提升的全过程。整体流程分为三个阶段：

```
┌────────── 入口阶段 ──────────┐    ┌────────── 循环阶段 ──────────────────┐
│                              │    │                                      │
│  注册画像 → 水平测评 → 路径规划 ──→ 每日学习 → 动态画像更新 → 任务调整 ──┘
│                              │    │   ↑                        │
│   (一次性，建立初始画像)        │    │   └────── 数据回流 ─────────┘
│                              │    │
└──────────────────────────────┘    │  观测层：进度追踪 + 效果预测 + 预警
                                    └──────────────────────────────────────┘
```

- **入口阶段**（一次性）：注册画像 → 水平测评 → 初始路径规划，建立用户初始画像和 CEFR 定级
- **循环阶段**（持续运行）：每日学习 →学习数据写入画像 → EMA 重算各维度分数 → 识别新短板 → 调整后续任务 → 继续学习，形成**"越学越精准"的正反馈闭环**
- **观测层**（伴随运行）：进度可视化、效果预测、预警提醒，全程监控学习状态但不参与闭环回流



### 1.1 注册与画像构建

```
用户注册 → 填写个人信息（年龄、学习目标、偏好） → 构建多维画像
```

用户首次使用系统时，通过手机号或邮箱注册账号，填写**年龄、学习目标（日常交流/考试备考/商务英语/出国旅行/兴趣爱好）等信息。**系统据此构建用户多维画像，作为后续个性化服务的**数据基础**。

### 1.2 水平智能测评

```
进入测评 → 自适应答题（听力/口语/阅读/语法四维度） → CEFR 定级 → 能力雷达图
```

注册完成后，用户进入水平测评环节。系统采用**自适应难度算法**，**根据用户答题情况动态调整题目难度**，从听力、口语、阅读、语法四个维度全面评估英语水平。测评完成后输出 **CEFR 等级（A1-C2）和各维度能力**雷达图，精准定位用户的优势与短板。

### 1.3 个性化学习路径规划

```
测评结果 + 用户画像 → 知识图谱匹配 → 拓扑排序 → 每日学习任务推送
```

**基于测评结果和用户画像**，系统利用**知识图谱**（129个知识点节点 + 292条前置依赖边）和 NetworkX 拓扑排序算法，为每位用户生成最优学习路径。每日自动推送学习任务，包括单词学习、发音跟读、AI 对话、听力训练等。

### 1.4 每日学习训练

学习者在系统内完成四大核心训练：



**AI 智能对话练习**

```
选择场景 → 语音输入 → ASR 转写 → LLM 生成回复 → TTS 语音输出 → 继续对话
```

支持餐厅点餐、酒店入住、商务谈判、学术讨论、旅行出行等 8 大真实场景，端到端语音交互延迟 ≤ 2 秒。对话结束后，系统自动将**发音评分和文本评分**（语法正确率、词汇丰富度、对话参与度）**摄入动态画像**。



**发音评测与纠错**

```
选择内容 → 跟读录音 → wav2vec2 声学分析 → GOP 音素评分 → 五维评分报告 → 纠音练习
```

用户跟读标准发音后，系统从音素准确度、重音、连读、语调、节奏五个维度进行精细评分。评分结果自动写入用户技能分数表，**触发画像重算**。



**情景角色扮演**

```
选择角色（面试者/服务员/导游等） → 多轮互动对话 → 四维评分报告
```

用户选择角色后与 AI 进行多轮互动，系统从角色贴合度、语言恰当性、流利度、语法准确性四个维度进行评分。



**语法纠错与润色**

```
输入文本或语音 → LLM 分析 → 错误标注 + 纠正版本 + 地道表达推荐
```

支持语音和文字**双模态输入**，实时识别时态、主谓一致、冠词、介词搭配等语法错误，提供纠正版本和更地道的表达方式。



### 1.5 动态画像更新 — 核心闭环（正反馈循环）

```
训练完成 → 分数摄入 → EMA 重算各维度 → 更新用户等级 → 重新识别短板 → 调整后续任务
```

这是系统"越学越精准"的关键机制，每次训练后自动触发：

| 步骤 | 触发时机 | 具体动作 |
|------|----------|----------|
| ① **分数摄入** | 发音评测/对话练习/任务完成 | `profile_updater.ingest_*()` 将评分写入 `UserSkillScore` 表 |
| ② **EMA 重算** | 每次分数摄入后自动调用 | 指数移动平均算法，新分数权重 30%，历史分数权重 70%，只计算最近 30 天 |
| ③ **等级更新** | EMA 重算完成后 | 根据综合分更新 `user_profiles.level_final`（A1-C2），用户画像等级随之变化 |
| ④ **短板识别** | 下次路径规划/推荐时 | 推荐服务读取**最新各维度 EMA 分数**，自动识别最低分维度作为当前**短板** |
| ⑤ 任务调整 | 每日任务生成时 | **优先推荐短板相关任务，难度匹配当前等级**，确保学习始终"对症下药" |

**举例说明**：用户初始测评等级为 B1，经过一周发音练习后，发音维度 EMA 分数从 55 提升到 68，但语法维度降至 50 成为新短板。系统自动将后续任务从"发音跟读"调整为"语法纠错 + 对话练习"，实现动态自适应。



### 1.6 学习进度可视化

```
学习数据汇聚 → 雷达图 + 趋势折线图 + 日历热力图 + 统计卡片
```

系统以可视化图表展示用户的多维度学习进步轨迹，用户可切换天/周/月/全部时间范围查看，清晰了解自己的**成长路径**。**雷达图展示的维度分数直接来自动态画像的 EMA 计算值**

### 1.7 学习效果预测与预警

```
历史数据 → 线性回归预测 → 预计达标时间 → 偏差预警 → 反馈调整学习路径
```

**系统基于用户历史学习数据进行线性回归分析，预测达到目标水平的时间和进度风险。当检测到连续未学习、学习时长下降超过 50%、发音得分停滞等异常情况时，自动触发预警提醒，并反馈调整学习路径。**

### 1.8 观测层 — 学习状态监控

观测层与循环阶段的核心区别：循环阶段**写入数据、驱动任务调整**，观测层**只读数据、展示分析**，不参与闭环回流。

| | 循环阶段 | 观测层 |
|------|----------|--------|
| 作用 | 发动机，驱动学习前进 | 仪表盘，看清当前情况 |
| 数据流 | 写入 `user_skill_scores`，触发 EMA 重算 | 只读取历史数据，不写入画像 |
| 影响闭环 | 是，直接改变后续任务 | 否，仅供用户和教师参考 |

包含三个功能（对应 `progress.py` + `prediction.py`）：

**① 进度可视化**
- 雷达图：四维能力分布（发音/语法/词汇/流利度）
- 趋势折线图：发音和流利度分数随时间变化，支持天/周/月/全部
- 日历热力图：每日学习活跃度一目了然
- 统计卡片：总任务数、连学天数、发音/对话练习次数和均分

**② 效果预测**
- 线性回归分析历史分数增长曲线
- 推算预计达到目标等级的剩余天数
- 例如："按当前进步速度，预计 45 天后达到 B2"

**③ 预警提醒**
- 连续 N 天未学习 → 推送提醒
- 学习时长下降超过 50% → 异常预警
- 发音分数在最近 14 天无提升 → 停滞预警

### 1.9 激励与社交

**游戏化闯关**

```
每日闯关 → 配音挑战 → 获得积分 → 解锁勋章 → 排行榜竞争
```

**学习社区**

```
语音挑战广场 → 讨论区发帖 → 加入学习小组 → 组队学习 → 互评互助
```

### 1.10 智能客服

智能客服"小语"采用 **RAG + 知识图谱 + LLM** 三重增强架构，支持文字和语音双模态输入，7×24 小时在线。

**核心流程**：

```
用户提问（文字/语音）
     ↓
┌── ① 语音输入：浏览器录音 → WhisperX ASR 转写
│
├── ② 知识图谱提取：LLM 识别用户提及的知识点（如"过去时"、"th发音"）
│         → kg_service.find_recommendations() 模糊匹配技能节点
│         → 返回前置依赖 + 推荐资料 + 易混淆技能 + CEFR等级
│
├── ③ RAG 检索：BGE 向量模型将问题向量化
│         → ChromaDB 语义搜索 FAQ + 产品文档，取 Top-3
│
├── ④ 上下文合并：KG 结果 + RAG 结果 → 统一注入 LLM system prompt
│
└── ⑤ LLM 生成回复：阿里千问 qwen-plus，支持流式 SSE 输出
         → 搜索日志写入 search_logs 表
```

**三大特色能力**：

| 能力 | 说明 |
|------|------|
| **RAG 增强** | FAQ 和产品文档预先向量化存入 ChromaDB，用户提问时检索最相关的 3 条，确保回答基于真实文档 |
| **知识图谱推荐** | 用户提到具体知识点时（如"过去时怎么学"），自动查询知识图谱返回前置依赖链 + 教学视频 + 易混淆技能 |
| **语音输入** | 浏览器端录音 16kHz 单声道 → 后端 WhisperX 转写 → 进入相同 RAG+KG 流水线 |

**前端交互**：
- 左栏：FAQ 分类快捷浏览（账号、学习功能、技术问题、会员支付，共 11+ 预设问答）
- 右栏：实时聊天界面 + 6 个快捷提问标签 + 语音录制按钮 + 流式打字动画
- 功能说明弹窗：向用户解释 RAG、知识图谱、语音输入三大能力

**后台管理**（运营端）：
- 知识库文档 CRUD + 单个/全量重新索引
- 搜索日志查看（按用户筛选），监控用户都在问什么

## 二、教师端 — 班级管理与作业点评的完整教学工具

教师端为教师提供班级管理、作业布置、学生评估的一站式工具。

### 2.1 班级管理

```
创建班级 → 生成邀请码 → 学生凭码加入 → 查看班级学生列表
```

教师创建班级后系统自动生成唯一邀请码，学生输入邀请码即可加入班级。教师可随时查看班级学生列表，了解每位学生的累计学习时长。

### 2.2 作业布置

```
选择班级 → 设置作业标题 → 选择作业类型 → 设定截止日期 → 发布作业
```

教师可向指定班级布置定制化口语作业，作业类型包括跟读练习、对话练习、角色扮演。学生端自动收到作业通知。

### 2.3 作业批阅与点评

```
查看学生提交 → 播放录音 → 在线评分 → 文字点评 → 学生收到反馈
```

教师查看学生提交的录音作业，系统自动给出 AI 初评分数作为参考，教师可调整评分并撰写文字点评。学生端实时收到教师的反馈。

### 2.4 学生能力报告

```
选择学生 → 能力雷达图 → 进步趋势 → 活动记录 → 薄弱点分析
```

教师可查看每位学生的详细能力报告，包括多维度能力雷达图、历史进步趋势、近期活动记录等，帮助教师精准发现学生的共性薄弱点，调整教学策略。

## 三、运营端 — 平台运营与数据监控的管理后台

运营端为平台运营人员提供用户管理、内容管理、数据分析和反馈处理的全套工具。

### 3.1 运营数据仪表盘

```
登录后台 → 运营看板 → 核心指标一览
```

运营看板展示平台核心运营指标：
- **DAU/MAU**：日活跃用户数 / 月活跃用户数
- **新增用户**：近 30 天注册趋势
- **留存率**：D1（次日留存）/ D7（七日留存）
- **内容统计**：各类学习资源数量分布
- **用户角色分布**：学习者 / 教师 / 管理员占比

### 3.2 用户管理

```
查看用户列表 → 搜索筛选 → 查看详情 → 禁用/启用账号 → 操作审计
```

运营人员可按用户名搜索、按角色筛选用户，查看用户详细信息和学习数据，对违规账号进行禁用或启用操作。

### 3.3 内容管理

```
选择内容类型 → 查看/新增/编辑/删除 → 素材库维护
```

运营人员管理平台全部学习内容，包括：
- **学习资源**：视频、音频、文章、练习题
- **配音素材**：影视片段、动画片段
- **挑战题库**：每日闯关题目、语音挑战题目

### 3.4 反馈管理

```
查看用户反馈 → 筛选状态 → 查看详情 → 回复处理 → 标记已处理
```

集中管理用户提交的反馈和投诉，支持按状态筛选（待处理/已回复/已关闭），运营人员可直接回复用户并标记处理状态。

### 3.5 操作日志审计

所有管理员操作自动记录到操作日志，包括操作人、操作类型、操作对象、操作时间，确保平台运营安全可追溯。

## 六、用户画像详解

用户画像分两层：**静态基础画像**（你是谁）和**动态技能画像**（你现在什么水平、哪里薄弱）。

### 6.1 静态基础画像（`user_profiles` 表）

注册时填写：年龄→年龄段（儿童/青少年/大学生/职场/中老年）、学习目标（日常交流/考试/商务/出国/兴趣）、兴趣标签（JSON）、自评等级、测评等级 `level_test`（首次测评 CEFR，**固定不变**）、最终等级 `level_final`（**随学习动态更新**）。

### 6.2 动态技能画像（EMA 驱动）

| 要素 | 说明 |
|------|------|
| `user_skill_scores` | 每次练习写入一条，记录四维度分数（发音/语法/词汇运用/流利度）+ 来源 + 子技能名 |
| `dimension_score_logs` | 每次 EMA 重算后记录四维度快照 + 综合分 + CEFR，用于趋势图 |
| EMA 算法 | `新分数×0.3 + 历史EMA×0.7`，仅计算最近 30 天 |
| 分数来源 | 发音评测→发音；对话语法→语法；对话词汇→词汇运用；对话参与度→流利度；测评→全部 |

### 6.3 更新闭环

```
练习 → 写入 user_skill_scores → EMA 重算 → 更新 level_final → 识别短板 → 下次任务补短板
```

## 七、任务推荐依据

推荐引擎是**动静结合**的，画像决定"该学什么、多难"，知识图谱提供"有哪些可学"。

### 7.1 每日任务生成（6 步）

| 步骤 | 依据 | 来源 |
|------|------|------|
| 短板优先 | 四维度 EMA 最低分 | 动态画像 |
| 目标加权 | `learning_goal` → 场景偏好（如商务→面试） | 静态画像 |
| CEFR 匹配 | `level_final` → 同等级知识图谱节点 | 动态画像 |
| 前置依赖 | 知识图谱技能前置关系 | 知识图谱 |
| 兴趣优选 | 资料标签 ∩ `interests` | 静态画像 |
| 去重 | 当天已有任务不重复生成 | — |

### 7.2 资料推荐（四因子评分）

```
评分 = 短板匹配×40% + 难度匹配×35% + 兴趣匹配×25%
最终分 = 评分 × 新颖度系数
```

- **短板匹配**：资料教授的 skill 是否属于用户 EMA 最低分维度
- **难度匹配**：资料 CEFR 与用户 `level_final` 差距
- **兴趣匹配**：资料标签与用户 `interests` 重叠度
- **新颖度**：7 天内推荐过扣分，disliked 归零

## 八、EMA 算法说明

EMA（指数移动平均）是一种**统计学平滑算法**，不产出分数，只加工分数。公式：

```
新EMA = 本次得分 × 0.3 + 历史EMA × 0.7
```

**在系统中的位置**：

```
发音评测(wav2vec2+GOP) → 五维原始分数（音素/重音/连读/语调/节奏）
                              ↓
                        EMA 平滑汇总为发音维度分数
                              ↓
                        更新 user_profiles.level_final
```

**为什么用 EMA**：避免画像等级因单次练习剧烈波动（比如今天 B2、明天 A1）。类比：发音评测是"考试打分"，EMA 是"算平时成绩"——30% 期末 + 70% 平时，一次考砸不会全崩。

**与发音评测的区别**：发音评测的五个维度分数（音素准确度、重音、连读、语调、节奏）由 wav2vec2 + GOP 声学模型直接产出，EMA 只负责事后对历史分数做加权平均。

## 九、知识图谱详解

知识图谱是一张**有向图**（NetworkX 内存图 + MySQL 持久化），应用启动时从 `kg_nodes` / `kg_edges` 表全量加载到内存，读操作直接查内存，写操作同步写 MySQL。

### 9.1 数据结构

**节点（129个）**：分 5 种类型

| 类型 | 数量 | 示例 |
|------|------|------|
| `cefr_level` | 6 | A1 入门 ~ C2 精通 |
| `skill:phoneme` | 44 | /θ/(think)、/iː/(sheep) 等英语音素 |
| `skill:grammar` | 21 | 一般现在时 → 现在完成时 → 被动语态，含前置依赖链 |
| `skill:vocabulary` | 12 | 食物、旅行、商务、科技等主题词汇 |
| `topic` | 15 | 餐厅点餐、工作面试、酒店入住等场景 |
| `material` | 30 | 10视频 + 10文章 + 10音频（含 URL/难度/时长/标签） |

**边（292条）**：6 种关系类型

| 关系 | 方向 | 含义 | 示例 |
|------|------|------|------|
| `BELONGS_TO` | skill/material → cefr | 属于某等级 | 现在完成时 → B1 |
| `HAS_PREREQ` | skill → skill | 前置依赖 | 现在完成时 → 一般过去时 |
| `SIMILAR_TO` | phoneme → phoneme | 易混淆音素 | /θ/ ↔ /ð/ |
| `TEACHES` | material → skill | 资料教授技能 | 视频"TH Sound" → /θ/、/ð/ |
| `COVERS` | material → topic | 资料覆盖场景 | 视频"Ordering Food" → 餐厅点餐 |

### 9.2 图遍历应用

| 场景 | 使用的图操作 | 说明 |
|------|-------------|------|
| **学习路径规划** | BFS + 拓扑排序 | 根据用户等级找到目标技能 → BFS 收集所有前置节点 → `nx.topological_sort` 排出学习顺序 |
| **每日任务生成** | `get_skills_by_cefr` + `get_materials_teaching` | 短板维度 → 同等级技能 → 教授该技能的资料 → 生成跟读/对话/听力任务 |
| **资料推荐** | `get_skills_for_dimension` + 图遍历 TEACHES 边 | 判断资料教授的 skill 是否匹配用户短板 |
| **智能客服** | `search_skills` + `get_skill_context` | 用户问"过去时怎么学" → 模糊搜索匹配技能 → 返回前置依赖 + 推荐资料 + 易混淆技能 |

### 9.3 核心设计

- **层级结构**：cefr_level → skill（音素/语法/词汇） → material（资料） → topic（场景）
- **前置依赖链**：例：一般现在时(A1) → 一般过去时(A1) → 现在完成时(B1) → 过去完成时(B2) → 第三条件句(C1)，保证学习路径不跳级
- **易混淆标注**：每个音素标注 2-3 个易混淆音素（SIMILAR_TO），发音练习时优先对比训练

### 9.4 完整示例：用户"过去完成时"学习路径生成

以 B1 等级用户为例，语法维度是当前短板，系统生成学习路径的过程：

**Step 1：找到目标技能**
```
用户 level_final = B1, 短板 = grammar
     ↓
知识图谱查询 get_skills_by_cefr("B1", "grammar")
     ↓
候选：[现在完成时, 过去进行时, 第一条件句, 被动语态, 动名词与不定式, ...]
     ↓
随机选择目标：skill:grammar_past_perfect（过去完成时，B2，略高于当前等级做挑战）
```

**Step 2：BFS 收集前置依赖链**
```
skill:grammar_past_perfect
  ├─ HAS_PREREQ → skill:grammar_present_perfect（现在完成时 B1）
  │    └─ HAS_PREREQ → skill:grammar_past_simple（一般过去时 A1）
  └─ HAS_PREREQ → skill:grammar_past_simple（一般过去时 A1）
```
BFS 收集到的子图节点：`{past_perfect, present_perfect, past_simple}`

**Step 3：拓扑排序**
```python
nx.topological_sort(subgraph)
# → [skill:grammar_past_simple, skill:grammar_present_perfect, skill:grammar_past_perfect]
```
学习顺序：一般过去时(A1) → 现在完成时(B1) → 过去完成时(B2)

**Step 4：匹配学习资料**
```
material:video_7 "Past Tense Mastery"  ──TEACHES→ skill:grammar_past_simple
material:video_9 "Present Perfect..."  ──TEACHES→ skill:grammar_present_perfect
```
现在完成时和过去完成时无直接教学视频，系统回退到生成对话/跟读任务，由 LLM 动态教学。

**Step 5：生成每日任务**
```
用户今日任务：
  1. 跟读练习 → 从 past_simple 关联的音素资料中选（phoneme 技能）
  2. 对话练习 → 匹配 B1 等级的场景（如餐厅点餐），LLM 对话中自然融入过去完成时
  3. 听力练习 → 匹配 B1 等级的音频资料
```

**关键点**：知识图谱本身不包含完整教学内容，它提供的是**技能之间的结构关系**和**技能与资料的关联**，具体教学由 LLM 和发音评测在运行时动态完成。

## 十、用户端技术栈详解（按业务闭环链路展开）

### 10.1 入口阶段

```
注册画像 → 水平测评 → 路径规划
```

**① 注册与画像构建**
- 前端 Vue 3 表单 → JWT 认证（python-jose + passlib bcrypt）
- 用户数据写入 MySQL `user_profiles` 表

**② 水平智能测评**
- **自适应难度**：delta 调整算法，答对升 0.5 级、答错降 0.5 级，A1-C2 区间浮动
- **客观题**（听力/阅读/语法）：MySQL 题库选择题，正确答案匹配判分
- **口语题**：浏览器录音 → WhisperX `small` int8 转写 → 阿里百炼 `qwen-plus` LLM 四维评分（内容相关性 25 + 语法 25 + 词汇 25 + 连贯性 25）
- 10 道题覆盖四维度：听力×3、口语×2、阅读×3、语法×2
- 综合分 = 四维度均分 → CEFR 定级 → 摄入动态画像

**③ 学习路径规划**
- **知识图谱**：NetworkX `DiGraph` 有向图（129 节点 + 292 边），MySQL 持久化
- BFS 收集技能前置依赖节点 → `nx.topological_sort()` 拓扑排序 → 排出学习顺序
- 结合用户 `level_final` + `learning_goal` + `interests` 生成初始学习路径

### 10.2 循环阶段 — 每日学习训练

```
每日学习 → 动态画像更新 → 任务调整 → 继续学习
```

#### 10.2.1 AI 智能对话

```
语音输入 → ASR → LLM → TTS → 语音输出（端到端 ≤ 2 秒）
```

| 环节 | 技术/模型 | 说明 |
|------|----------|------|
| **ASR 语音转写** | WhisperX `small` int8 (CPU) | 词级时间戳对齐，`load_align_model` |
| **LLM 对话生成** | 阿里百炼 `qwen-plus` | 8 大真实场景，SSE 流式输出 |
| **TTS 语音合成** | 微软 Edge TTS `edge-tts` | 4 种音色，默认 `en-US-JennyNeural` |
| **发音评分** | wav2vec2 + GOP | 复用发音评测管线，5 维音素评分 |
| **文本评分** | LLM `score_conversation` | 语法正确率 + 词汇丰富度 + 对话参与度 |
| **综合分** | 年龄段自适应加权 | `语音均分 × pron_weight + 文本均分 × text_weight` |

**对话结束后自动摄入画像**：发音维度 → pronunciation，语法正确率 → grammar，词汇丰富度 → vocabulary，对话参与度 → fluency

#### 10.2.2 发音评测与纠错

```
跟读录音 → wav2vec2 声学分析 → GOP 音素评分 → 五维报告
```

| 环节 | 技术/模型 | 说明 |
|------|----------|------|
| **声学模型** | `WAV2VEC2_ASR_BASE_960H`（9500 万参数） | torchaudio 预训练模型，96 类 CTC 字素标签 |
| **音素转换** | `g2p-en` G2P | 文本 → ARPABET 音素映射 |
| **强制对齐** | CTC Viterbi 解码 | 手写 DP 实现，帧级音素对齐 |
| **GOP 评分** | 平均 logSoftmax 概率 | 每帧计算 → 映射到 0-100 分 |
| **重音位置** | librosa RMS 能量包络 | 变异系数分析 |
| **语调曲线** | librosa `pyin` F0 提取 | 线性回归斜率（半音/秒） |
| **连读表现** | WhisperX 词级时间戳 | G2P 辅音-元音条件判断 |
| **节奏感** | CTC 对齐音素时长 | 变异系数 CV |

**五个维度的分数全部摄入画像 → pronunciation 维度**

#### 10.2.3 情景角色扮演

```
选择角色 → 多轮互动对话 → 四维评分
```

- **ASR → LLM → TTS**：复用对话管线，LLM prompt 注入角色设定
- **8 种角色**：面试者、服务员、导游、医生、教师、客服、前台、同事
- **四维评分**（LLM 评估）：角色贴合度、场景礼仪、专业术语、应对能力
- **综合分**：`角色平均分 × 0.6 + 发音平均分 × 0.4`
- 评分结果摄入动态画像

#### 10.2.4 语法纠错与润色

```
输入文本或语音 → LLM 分析 → 错误标注 + 纠正 + 地道表达
```

- **模型**：阿里百炼 `qwen-plus`，temperature=0.1，max_tokens=150，timeout=8s
- **输出格式**：JSON 错误列表 `{original, correction, error_type, explanation}`
- **错误类型**：时态、冠词、主谓一致、介词搭配、拼写、词序等
- **双模态输入**：文本直接纠错 / 语音先经 WhisperX 转写再纠错
