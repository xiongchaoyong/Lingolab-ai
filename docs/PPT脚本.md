
### Slide 4 — 核心业务（下）：从练习到成长闭环

**纯用户视角，两张截图级描述**

```
🧑 用户每天做的两件事 + 看到的结果：


  ┌─────────────────────────────────────────────────────────┐
  │ 核心练习 ① AI 语音对话 — 像跟真人外教聊天                      │
  │                                                         │
  │   选一个场景（点餐 / 商务谈判 / 学术讨论 / 面试...）            │
  │   → AI 开口说话 → 我语音回复 → AI 继续对话                   │
  │   → 对话中实时给出语法纠正和中文翻译                          │
  │   → 聊完了，给出综合评分：发音、语法、词汇、流利度                │
  └─────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────┐
  │ 核心练习 ② 发音评测 — 精确到每个音的对错                        │
  │                                                         │
  │   选一句话，先听标准发音 → 自己跟读录音                        │
  │   → 系统打分：音素准不准、重音对不对、语调自不自然               │
  │   → 每个读错的音用红色标出来，告诉你舌头该怎么放                  │
  └─────────────────────────────────────────────────────────┘
                              ↓
  ┌─────────────────────────────────────────────────────────┐
  │ 用户每天看到的「我的进步」                                    │
  │                                                         │
  │   首页三件事：                                            │
  │   · 雷达图 — 各维度能力分布，弱项一目了然                     │
  │   · 趋势图 — 过去30天分数变化，哪个在涨哪个在跌                │
  │   · AI预测 — 「按当前速度，预计 32 天后达到 C1」              │
  └─────────────────────────────────────────────────────────┘


        ┌──────────────── 完整闭环 ────────────────┐
        │                                          │
        │   测评定位 → 每日推荐 → 练习打分 → 画像更新   │
        │       ↑                              ↓    │
        │       └──── 越练越精准，越练越匹配 ←────┘    │
        └──────────────────────────────────────────┘
```


两个核心练习：语音对话像跟真人外教聊天，发音评测精确告诉你每个音错在哪里。用户每天看到的结果：雷达图、趋势图、AI 预测。最后回到闭环图——越练越精准、越练越匹配。

### Slide 6 — AI 协作与经验总结

**一页全收**

```
🤖 AI 协作方式

  团队：3 人 + Claude Code + DeepSeek

  ┌────────┬────────┬────────┬────────┐
  │ 40天    │ 3亿   │ 3.1万   │ 7.4万   │
  │ 开发周期  │ token消耗  │ 代码行数  │ 文档字数  │
  └────────┴────────┴────────┴────────┘


  🧠 智能体 + 自定义技能

  需求分析师 — 自动分析需求，生成PRD、用户故事、验收标准
  需求澄清（requirements-clarity）— 100分评分系统，<90分不编码，避免方向性返工
  模块分析（module-analysis）— 自动生成用例图/流程图并插入Word文档


  💡 协作技巧

  📋 Plan Mode                            📦 压缩上下文
    先出计划 → 人工确认 → 再写代码                单模块生成，逐步迭代
    避免方向性错误，减少返工                       防止一次生成太多文件导致质量下降

  📜 CLAUDE.md 项目契约                     📝 ai-log.md 经验积累
    7条禁止事项 + 技术栈 + 代码规范                每次犯错记录，下次不犯
    AI 与团队的行为底线                          经验持续沉淀到项目文档


  ⚠️ 踩过的坑                                💡 核心结论

  跳过需求澄清直接编码 → 方向性返工                  
  AI 一次生成太多文件 → 质量下降                    AI 大幅提升了编码效率，但产品该做成什么样、
  错误不记录 → 重复踩坑                            架构怎么设计、模块如何拆解——
                                                   这些决策仍然需要具备软件工程思维的人来主导。
                                                   
                                                   AI 负责"怎么写"，人负责"写什么"和"为什么写"。
```


讲清楚四件事：智能体、技能、协作技巧、踩坑与结论。控制在 60 秒内。
