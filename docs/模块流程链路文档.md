# 模块流程链路文档

> 逐模块梳理功能流程与技术架构，供答辩和代码审查使用。

---

## 模块 1：用户注册与多维度画像

### 一、功能流程

#### 1.1 注册流程

```
用户打开 /register 页面
  → 填写表单：用户名、邮箱、密码、确认密码、年龄、学习目标、兴趣标签
  → 前端表单验证（正则校验用户名/邮箱/密码格式）
  → 点击「注册并开始测评」
  → 调用 authStore.register()
  → 成功后存 Token 到 localStorage + Pinia
  → 路由跳转到 /assessment（水平测评）
```

#### 1.2 登录流程

```
用户打开 /login 页面
  → 输入用户名 + 密码
  → 点击登录
  → 调用 authStore.login()
  → 后端验证密码 + 检查 is_active
  → 成功后返回 JWT + assessment_completed 状态
  → 前端存 Token，根据 redirect 字段跳转：
      ├─ assessment_completed = false → /assessment
      └─ assessment_completed = true  → /home
```

#### 1.3 个人资料查看与编辑

```
用户打开 /profile 页面
  → onMounted 调用 authStore.fetchProfile() → GET /api/auth/profile
  → 展示只读信息（用户名、邮箱、年龄归类、CEFR 等级）
  → 可编辑字段：学习目标（下拉）、兴趣标签（多选）
  → 点击「保存修改」→ PUT /api/auth/profile
  → 后端乐观锁校验 version 字段，并发安全
```

#### 1.4 Token 自动刷新

```
任意 API 请求返回 401
  → axios 响应拦截器捕获
  → 检查是否已在刷新中（isRefreshing 标志）
  → 若未在刷新：调用 POST /api/auth/token/refresh
  → 后端用当前有效 Token 换取新 Token（24h 有效期）
  → 前端更新 localStorage + 重试原始请求
  → 若刷新失败：清除登录状态，提示重新登录
  → 若已在刷新：请求加入 pendingRequests 队列，等待刷新完成后重试
```

#### 1.5 路由守卫

```
每次路由切换 → router.beforeEach 守卫：
  ├─ 游客路由（/login, /register）+ 已登录 → 重定向 /
  ├─ 需认证路由 + 未登录 → 重定向 /
  ├─ 已完成测评 → 禁止再访问 /assessment → 重定向 /
  ├─ 未完成测评 + 非豁免路径 → 强制跳转 /assessment
  └─ 角色路由（/teacher/*, /admin/*）→ 角色不匹配 → 重定向 /
```

#### 1.6 管理员禁用/恢复账号

```
管理员调用 POST /api/auth/admin/toggle-status
  → 验证当前用户 role == "admin"
  → 不能禁用自己
  → 修改目标用户 is_active 字段
  → 被禁用用户下次请求时 get_current_user 拦截（is_active != 1 → 401）
```

### 二、技术架构

| 层次 | 技术 | 说明 |
|------|------|------|
| 前端页面 | Vue 3 + Element Plus | RegisterView / LoginView / ProfileView |
| 前端状态 | Pinia + localStorage | Token 持久化，userInfo 响应式管理 |
| 前端路由 | Vue Router 4 + beforeEach 守卫 | 5 层权限检查（guest/auth/assessment/role） |
| 前端 HTTP | Axios + 请求/响应拦截器 | 自动附带 Token，401 自动刷新 + 重试队列 |
| 后端路由 | FastAPI | `api/auth.py` — 6 个端点（register/login/profile/update/refresh/toggle） |
| 认证 | JWT (python-jose) | HS256 签名，24h 有效期，无状态 |
| 密码安全 | bcrypt (passlib) | 不可逆哈希 + salt |
| 并发控制 | 乐观锁 | user_profiles.version 字段 + WHERE 条件更新 |
| ORM | SQLAlchemy | `UserProfile` 模型映射 `user_profiles` 表（20+ 字段） |
| 校验 | Pydantic | RegisterRequest/LoginRequest/ProfileUpdateRequest 请求校验 |

## 模块 2：英语水平智能测评

### 一、功能流程

#### 2.1 开始测评

```
用户注册成功后自动跳转 /assessment
  → 路由守卫检查：已完成测评 → 禁止重测 → 重定向 /
  → onMounted 调用 store.startAssessment()
  → 先检查 localStorage 是否有未完成进度：
      ├─ 有进度 → 调用 POST /api/assessment/restore 恢复后端会话
      │   ├─ 恢复成功 → 继续上次题目
      │   └─ 恢复失败（会话过期）→ 清除旧数据，走新建流程
      └─ 无进度 → 调用 POST /api/assessment/start 创建新会话
  → 后端返回 session_id + 第一题 + 总题数 + 当前难度
  → 前端保存进度到 localStorage
```

#### 2.2 客观题答题

```
用户看到题目（听力/阅读/语法）
  → 题目从 DB 按维度 + CEFR 随机抽取
  → 用户选择 A/B/C/D 选项
  → 点击「确认答案」
  → 调用 POST /api/assessment/answer（FormData: session_id, question_id, answer）
  → 后端比对正确选项 → 判分（100/0）
  → 累计维度分数 → 自适应调整难度（≥60 升 0.5 级，<60 降 0.5 级）
  → 返回下一题 + 新难度等级
  → 前端更新题目展示 + 进度条
```

#### 2.3 口语题答题

```
用户看到口语题
  → 前端展示 VoiceRecorder 组件（3 秒准备 + 最长 45 秒录音）
  → 用户录音 → 完成后触发 handleSpeakingComplete
  → 调用 POST /api/assessment/answer（FormData: session_id, question_id, answer="", audio 文件）
  → 后端处理：
      ├─ 保存音频到临时文件
      ├─ ffmpeg 转码为 WAV 16kHz
      ├─ WhisperX 转写 → 文本 transcript
      ├─ LLM（DashScope qwen-plus）四维评分（内容/语法/词汇/连贯，各 0-25）
      ├─ 保存音频到 uploads/assessment/{session_id}/
      └─ 返回得分 + 下一题
  → 前端显示「评分中...」加载状态
```

#### 2.4 全对/全错追加题

```
基础 10 题答完
  → 后端检查所有题目得分：
      ├─ 10 题全答对（得分≥60）→ 追加 1 道 C2 口语确认题
      ├─ 10 题全答错（得分<60）→ 追加 1 道 A1 听力基础题
      └─ 正常情况 → 直接结束
  → 追加题不影响基础 10 题的维度分数计算
```

#### 2.5 完成测评

```
所有题目答完（含追加题）
  → 调用 POST /api/assessment/complete
  → 后端计算：
      ├─ 四维均分（听力/口语/阅读/语法各维度平均）
      ├─ 综合分 = 四维均分的平均
      ├─ CEFR 定级（A1:0-20 / A2:21-40 / B1:41-60 / B2:61-80 / C1:81-95 / C2:96-100）
      ├─ 短板维度（最低分维度 + 学习建议）
      └─ 更新 user_profiles：level_test + level_final + assessment_completed=1
  → 前端清除 localStorage 进度
  → 跳转 /assessment/result 展示报告
```

#### 2.6 中途退出与恢复

```
用户点击「退出」或关闭页面
  → store.saveProgress() 保存到 localStorage（session_id + 当前题目 + 已答数 + 难度）
  → 下次进入 /assessment → startAssessment() 检测到 localStorage 有进度
  → 调用 POST /api/assessment/restore
  → 后端从 assessment_records 表重建会话状态（反推已答题目 + 当前难度）
  → 继续从上次中断的题目开始
```

### 二、技术架构

| 层次 | 技术 | 说明 |
|------|------|------|
| 前端页面 | Vue 3 + Element Plus | AssessmentView（答题页） + AssessmentResult（结果页） |
| 前端组件 | VoiceRecorder | 录音组件（MediaRecorder API，WebM 格式） |
| 前端状态 | Pinia Store | `assessment.js` — 会话/题目/进度/评分状态管理 |
| 前端持久化 | localStorage | 中断恢复：session_id + 当前题目 + 进度 |
| 后端路由 | FastAPI | `api/assessment.py` — 5 个端点（start/answer/complete/restore/submit） |
| 会话管理 | 内存字典 + DB 双写 | `_sessions` dict 存活跃会话，assessment_records 持久化 |
| 自适应算法 | CEFR 数值映射 | A1-C2 → 1.0-6.0，得分≥60 升 0.5 级，钳制 [1.0, 6.0] |
| ASR | WhisperX small (int8) | 口语题语音转文字 |
| LLM 评分 | DashScope qwen-plus | 口语题四维评分（内容/语法/词汇/连贯） |
| 音频处理 | ffmpeg + 转码 | WebM → WAV 16kHz 单声道 |
| 题库 | MySQL assessment_questions | 30 题（A2:9/B1:11/B2:10），按维度+难度分类 |
| ORM | SQLAlchemy | AssessmentQuestion + AssessmentRecord 模型 |
| 校验 | Pydantic | QuestionItem / AssessmentStartResponse / AssessmentAnswerResponse |
