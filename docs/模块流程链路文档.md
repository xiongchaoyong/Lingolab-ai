## 模块 1：用户注册与多维度画像

### 一、功能流程

#### 1.1 注册流程

```
用户打开 /register 页面
  → 填写表单：用户名、邮箱、密码、确认密码、年龄、学习目标、兴趣标签
  → 前端表单验证（正则校验用户名/邮箱/密码格式）
  → 点击「注册并开始测评」
  → 调用 authStore.register()
  → 成功后存 Token 到 localStorage + Pinia
  → 路由跳转到 /assessment（水平测评）
```

#### 1.2 登录流程

```
用户打开 /login 页面
  → 输入用户名 + 密码
  → 点击登录
  → 调用 authStore.login()
  → 后端验证密码 + 检查 is_active
  → 成功后返回 JWT + assessment_completed 状态
  → 前端存 Token，根据 redirect 字段跳转：
      ├─ assessment_completed = false → /assessment
      └─ assessment_completed = true  → /home
```

#### 1.3 个人资料查看与编辑

```
用户打开 /profile 页面
  → onMounted 调用 authStore.fetchProfile() → GET /api/auth/profile
  → 展示只读信息（用户名、邮箱、年龄归类、CEFR 等级）
  → 可编辑字段：学习目标（下拉）、兴趣标签（多选）
  → 点击「保存修改」→ PUT /api/auth/profile
  → 后端乐观锁校验 version 字段，并发安全
```

#### 1.4 Token 自动刷新

```
任意 API 请求返回 401
  → axios 响应拦截器捕获
  → 检查是否已在刷新中（isRefreshing 标志）
  → 若未在刷新：调用 POST /api/auth/token/refresh
  → 后端用当前有效 Token 换取新 Token（24h 有效期）
  → 前端更新 localStorage + 重试原始请求
  → 若刷新失败：清除登录状态，提示重新登录
  → 若已在刷新：请求加入 pendingRequests 队列，等待刷新完成后重试
```

#### 1.5 路由守卫

```
每次路由切换 → router.beforeEach 守卫：
  ├─ 游客路由（/login, /register）+ 已登录 → 重定向 /
  ├─ 需认证路由 + 未登录 → 重定向 /
  ├─ 已完成测评 → 禁止再访问 /assessment → 重定向 /
  ├─ 未完成测评 + 非豁免路径 → 强制跳转 /assessment
  └─ 角色路由（/teacher/*, /admin/*）→ 角色不匹配 → 重定向 /
```

#### 1.6 管理员禁用/恢复账号

```
管理员调用 POST /api/auth/admin/toggle-status
  → 验证当前用户 role == "admin"
  → 不能禁用自己
  → 修改目标用户 is_active 字段
  → 被禁用用户下次请求时 get_current_user 拦截（is_active != 1 → 401）
```

### 二、技术架构

| 层次 | 技术 | 说明 |
|------|------|------|
| 前端页面 | Vue 3 + Element Plus | RegisterView / LoginView / ProfileView |
| 前端状态 | Pinia + localStorage | Token 持久化，userInfo 响应式管理 |
| 前端路由 | Vue Router 4 + beforeEach 守卫 | 5 层权限检查（guest/auth/assessment/role） |
| 前端 HTTP | Axios + 请求/响应拦截器 | 自动附带 Token，401 自动刷新 + 重试队列 |

| 密码安全 | bcrypt (passlib) | 不可逆哈希 + salt |
| 并发控制 | 乐观锁 | user_profiles.version 字段 + WHERE 条件更新 |
| ORM | SQLAlchemy | `UserProfile` 模型映射 `user_profiles` 表（20+ 字段） |
| 校验 | Pydantic | RegisterRequest/LoginRequest/ProfileUpdateRequest 请求校验 |

## 模块 3：个性化学习路径规划

### 一、功能流程

#### 3.1 每日任务生成

```
用户登录后进入「学习路径」页面
  → onMounted 调用 store.fetchTasks()
  → GET /api/learning-path/tasks
  → 后端检查 daily_tasks 表今日是否已有任务：
      ├─ 有 → 直接返回已有任务
      └─ 无 → 执行六步生成法：
          ① 短板优先 → 从 user_skill_scores / 测评记录取最低分维度
          ② 目标加权 → learning_goal 映射场景偏好（日常/考试/商务/出国/兴趣）
          ③ CEFR 匹配 → 图查找 BELONGS_TO 同等级的技能节点
          ④ 前置依赖 → 检查技能前置链是否满足（HAS_PREREQ）
          ⑤ 兴趣优选 → 资料标签 ∩ 用户兴趣标签
          ⑥ 写入 daily_tasks → 返回 3 个任务（跟读+对话+听力各 1 个）
  → 前端展示任务卡片列表 + 进度条（done/total）
```

#### 3.2 任务操作

```
跳过任务：
  → POST /api/learning-path/tasks/{id}/skip
  → 更新 status="skipped" + skip_reason
  → 返回更新后的任务

换一个：
  → POST /api/learning-path/tasks/{id}/replace
  → 删除旧任务 → 生成同类型新任务（随机选取同 CEFR 等级的技能/场景/资料）
  → 返回新任务

调整难度：
  → POST /api/learning-path/tasks/{id}/adjust-difficulty（direction: easier/harder）
  → CEFR 等级 ±1 级（钳制 A1-C2）
  → 返回更新后的任务

完成任务：
  → POST /api/learning-path/tasks/{id}/complete（score + duration_seconds）
  → 更新 status="completed" + completed_at
  → profile_updater.ingest_task_score() 摄入分数到动态画像
```

#### 3.3 历史记录

```
用户展开「学习历史」区域
  → GET /api/learning-path/history?days=7
  → 后端查询最近 N 天的 daily_tasks
  → 按日期分组：每日的任务状态序列 + 完成数 + 总数 + 学习分钟数
  → 前端展示日历列表（done/skipped/pending 图标 + 统计）
```

#### 3.4 资料推荐

```
用户进入「资料推荐」页面
  → GET /api/recommendations/
  → 后端执行四因子评分推荐：
      ① 短板匹配 (40%) → 资料 TEACHES 的技能是否属于用户短板维度
      ② 难度匹配 (35%) → 资料 CEFR 与用户 level_final 差值
      ③ 兴趣匹配 (25%) → 资料标签 ∩ 用户兴趣标签
      ④ 新颖度（乘性因子）→ 7 天内推荐过打折，disliked 归零
  → 按分数降序，取视频×2 + 文章×2 + 音频×2
  → 写入 material_recommendations 表
  → 返回 6 条推荐资料
```

#### 3.5 资料交互

```
用户点击「不感兴趣」：
  → POST /api/recommendations/{id}/dislike
  → 更新 action="disliked"
  → 后续推荐该资料新颖度归零，不再出现

用户点击资料：
  → POST /api/recommendations/{id}/click（action: view/complete）
  → 更新 action + viewed_at

用户点击「换一批」：
  → POST /api/recommendations/refresh
  → 每日限 3 次手动刷新（首次加载不计入）
  → 超限返回 HTTP 429
  → 重新计算四因子评分 → 写入新推荐记录
```

### 二、技术架构

| 层次 | 技术 | 说明 |
|------|------|------|
| 前端页面 | Vue 3 + Element Plus | LearningPathView（任务卡片） + RecommendationView（资料列表） |
| 前端状态 | Pinia Store | `learning_path.js` — 任务/进度/操作状态管理 |
| 前端路由 | Vue Router | `/learning-path` + `/recommendations` |
| 后端路由 | FastAPI | `api/learning_path.py` — 6 个端点（tasks/skip/replace/adjust/complete/history） |
| 后端路由 | FastAPI | `api/recommendation.py` — 4 个端点（GET //dislike/refresh/click） |
| 知识图谱 | NetworkX DiGraph | 129 节点 + 292 边，启动时从 MySQL 全量加载到内存 |
| 图遍历 | BFS + 拓扑排序 | `get_prerequisite_chain()` 收集前置依赖 → `nx.topological_sort()` |
| 推荐算法 | 四因子评分 | 短板 40% + 难度 35% + 兴趣 25%，乘以新颖度因子 |
| 任务生成 | 六步规则引擎 | 短板→目标→CEFR→前置依赖→兴趣→写入 DB |
| 画像更新 | ProfileUpdater | 任务完成后 EMA 摄入分数到 user_skill_scores |
| ORM | SQLAlchemy | KGNode / KGEdge / DailyTask / MaterialRecommendation / LearningMaterial / MaterialRecord |
| 校验 | Pydantic | TaskItem / DailyTasksResponse / MaterialItem / RecommendationsResponse |
## 模块 2：英语水平智能测评

### 一、功能流程

#### 2.1 开始测评

```
用户注册成功后自动跳转 /assessment
  → 路由守卫检查：已完成测评 → 禁止重测 → 重定向 /
  → onMounted 调用 store.startAssessment()
  → 先检查 localStorage 是否有未完成进度：
      ├─ 有进度 → 调用 POST /api/assessment/restore 恢复后端会话
      │   ├─ 恢复成功 → 继续上次题目
      │   └─ 恢复失败（会话过期）→ 清除旧数据，走新建流程
      └─ 无进度 → 调用 POST /api/assessment/start 创建新会话
  → 后端返回 session_id + 第一题 + 总题数 + 当前难度
  → 前端保存进度到 localStorage
```

#### 2.2 客观题答题

```
用户看到题目（听力/阅读/语法）
  → 题目从 DB 按维度 + CEFR 随机抽取
  → 用户选择 A/B/C/D 选项
  → 点击「确认答案」
  → 调用 POST /api/assessment/answer（FormData: session_id, question_id, answer）
  → 后端比对正确选项 → 判分（100/0）
  → 累计维度分数 → 自适应调整难度（≥60 升 0.5 级，<60 降 0.5 级）
  → 返回下一题 + 新难度等级
  → 前端更新题目展示 + 进度条
```

#### 2.3 口语题答题

```
用户看到口语题
  → 前端展示 VoiceRecorder 组件（3 秒准备 + 最长 45 秒录音）
  → 用户录音 → 完成后触发 handleSpeakingComplete
  → 调用 POST /api/assessment/answer（FormData: session_id, question_id, answer="", audio 文件）
  → 后端处理：
      ├─ 保存音频到临时文件
      ├─ ffmpeg 转码为 WAV 16kHz
      ├─ WhisperX 转写 → 文本 transcript
      ├─ LLM（DashScope qwen-plus）四维评分（内容/语法/词汇/连贯，各 0-25）
      ├─ 保存音频到 uploads/assessment/{session_id}/
      └─ 返回得分 + 下一题
  → 前端显示「评分中...」加载状态
```

#### 2.4 全对/全错追加题

```
基础 10 题答完
  → 后端检查所有题目得分：
      ├─ 10 题全答对（得分≥60）→ 追加 1 道 C2 口语确认题
      ├─ 10 题全答错（得分<60）→ 追加 1 道 A1 听力基础题
      └─ 正常情况 → 直接结束
  → 追加题不影响基础 10 题的维度分数计算
```

#### 2.5 完成测评

```
所有题目答完（含追加题）
  → 调用 POST /api/assessment/complete
  → 后端计算：
      ├─ 四维均分（听力/口语/阅读/语法各维度平均）
      ├─ 综合分 = 四维均分的平均
      ├─ CEFR 定级（A1:0-20 / A2:21-40 / B1:41-60 / B2:61-80 / C1:81-95 / C2:96-100）
      ├─ 短板维度（最低分维度 + 学习建议）
      └─ 更新 user_profiles：level_test + level_final + assessment_completed=1
  → 前端清除 localStorage 进度
  → 跳转 /assessment/result 展示报告
```

#### 2.6 中途退出与恢复

```
用户点击「退出」或关闭页面
  → store.saveProgress() 保存到 localStorage（session_id + 当前题目 + 已答数 + 难度）
  → 下次进入 /assessment → startAssessment() 检测到 localStorage 有进度
  → 调用 POST /api/assessment/restore
  → 后端从 assessment_records 表重建会话状态（反推已答题目 + 当前难度）
  → 继续从上次中断的题目开始
```

## 模块 4：智能语音对话练习

### 一、功能流程

#### 4.1 开始对话

```
用户进入「AI 对话」页面
  → 选择场景（自我介绍/问路/购物/餐厅）
  → 点击「开始对话」
  → 调用 POST /api/conversation/start（或 /stream/start 流式版）
  → 后端：
      ├─ 创建内存会话（_sessions dict）+ DB 会话（conversation_sessions）
      ├─ 根据场景生成 AI 开场白 Prompt
      ├─ LLM（DashScope qwen-plus）生成开场白
      └─ 返回 session_id + AI 开场白文本
  → 流式版：SSE 逐 token 返回 + 后台 TTS 预取
  → 前端展示对话界面 + 播放 AI 语音
```

#### 4.2 用户说话

```
用户点击麦克风录音
  → 前端 VoiceRecorder 录音（MediaRecorder API，WebM 格式）
  → 录音完成 → 上传音频到 POST /api/conversation/speak（或 /stream/speak）
  → 后端处理管线：
      ├─ ffmpeg 转码 WebM → WAV 16kHz
      ├─ WhisperX ASR 转写 → 文本 + 词级时间戳
      ├─ 算法流利度计算（维度1-3：wpm/停顿频率/重复率，静默存储）
      ├─ LLM 语法纠错（asyncio.create_task 并行，不增加延迟）
      ├─ LLM 生成回复（chat_stream SSE 逐 token）
      ├─ 持久化用户消息 + AI 回复到 conversation_messages
      └─ 后台 TTS 预取（Edge TTS 缓存音频块）
  → 前端 SSE 接收：
      ├─ asr 事件 → 显示用户转写文本
      ├─ token 事件 → 逐字显示 AI 回复
      ├─ grammar 事件 → 显示语法纠错卡片（可折叠）
      └─ done 事件 → 对话完成标记 + TTS 音频 URL
  → 最多 10 轮（MAX_CONVERSATION_ROUNDS = 10）
```

#### 4.3 TTS 语音播放

```
前端获取 AI 回复后
  → 请求 GET /api/conversation/tts/cached/{session_id}/{round_key}
  → 后端从内存 TTS 缓存流式返回 MP3
  → 前端 <audio> 播放，边下载边播放
  → 若缓存未就绪，轮询等待（50ms 间隔）
```

#### 4.4 结束对话与评分

```
达到 10 轮或用户点击「结束对话」
  → 调用 POST /api/conversation/end
  → 后端双层评分体系：
      ├─ 语音维度（wav2vec2）：
      │   对每段用户音频评测五维（音素准确度/重音/语调/连读/节奏）
      │   → 各维度取平均
      ├─ 文本维度（LLM）：
      │   语法正确率 + 词汇丰富度 + 对话参与度（各含 feedback/strengths/weaknesses）
      ├─ 综合分 = 语音均分 × 50% + 文本均分 × 50%
      ├─ 流利度评估：
      │   算法维度（wpm/停顿/重复）+ LLM 维度（语法/相关性）
      │   → 五维汇总 → 分段评级（优秀/良好/中等/初级/入门）
      └─ 持久化：更新 conversation_sessions 评分 + ProfileUpdater 摄入分数
  → 前端展示综合报告（综合分→语音评测→文本评测→流利度→对话记录→改进建议）
```

## 模块 5：流利度与完整性评估

### 一、功能流程

#### 5.1 每轮流利度静默评分

```
用户每说完一轮（POST /api/conversation/stream/speak）
  → ASR 转写完成后，自动触发算法流利度计算：
      ├─ 维度1 语速(wpm)：单词数 / 说话时长（分钟），满分 25
      │   理想范围 100-120 wpm，偏差按比例扣分
      ├─ 维度2 停顿频率：词间 gap > 0.5s 计为停顿，满分 20
      │   <2次/分钟满分，<5次良好，>10次差
      └─ 维度3 重复率：连续重复词 + 2-gram 重复，满分 20
          <5%满分，<10%良好，>20%差
  → 结果静默存储到内存会话 fluency_scores[]
  → 同时持久化到 conversation_messages.fluency_scores 列
  → 用户无感知，不增加对话延迟
```

#### 5.2 对话结束流利度汇总

```
对话结束（POST /api/conversation/end）
  → 后端汇总所有轮次的流利度数据：
      ├─ 算法维度（已完成）：语速/停顿/重复 各轮平均
      ├─ LLM 维度（对话结束时调用）：
      │   维度4 语法正确性（满分 20）— LLM 逐轮评估语法错误
      │   维度5 内容相关性（满分 15）— LLM 评估回答是否切题
      ├─ 五维综合分 = 各轮（语速+停顿+重复+语法+相关性）的平均
      ├─ 分段评级：85-100 优秀 / 70-84 良好 / 55-69 中等 / 40-54 初级 / <40 入门
      └─ 最佳轮次识别 + 维度平均统计
  → 返回流利度报告：
      {
        overall: 78,
        grade: "良好",
        rounds: [{round, text, wpm, pause, rep, grammar, relevance, total}, ...],
        best_round: 3,
        dimension_averages: {wpm_avg, pause_avg, repetition_avg},
        suggestions: "..."
      }
```

#### 5.3 流利度报告展示

```
前端综合报告页（ConversationEndResponse.fluency）
  → 展示：
      ├─ 综合分 + 评级标签
      ├─ 五维雷达图（语速/停顿/重复/语法/相关性）
      ├─ 逐轮详情卡片（每轮五维得分 + 文本）
      ├─ 最佳轮次高亮
      └─ 改进建议
```

### 二、技术架构

| 层次 | 技术 | 说明 |
|------|------|------|
| 算法引擎 | fluency.py | 三个纯函数：assess_algorithmic() + aggregate_fluency() + _detect_repetitions() |
| 语速计算 | ASR 词级时间戳 | WhisperX words[] → 首词 start 到末词 end = 说话时长 |
| 停顿检测 | 词间 gap | words[i].start - words[i-1].end > 0.5s → 停顿 |
| 重复检测 | 连续重复 + 2-gram | 相邻重复词 + 3-gap 内重复 bigram |
| LLM 评分 | DashScope qwen-plus | score_fluency() 评估语法正确性 + 内容相关性 |
| 持久化 | SQLAlchemy | conversation_messages.fluency_scores (JSON) |
| 满分 | 100 | 语速 25 + 停顿 20 + 重复 20 + 语法 20 + 相关性 15 |

## 模块 6：AI 语法纠错与润色

### 一、功能流程

#### 6.1 独立文本纠错

```
用户打开「语法纠错」页面
  → 选择输入模式（文本/语音）+ CEFR 等级
  → 文本模式：输入英文句子 → 点击「检查语法」
  → 调用 POST /api/grammar/correct（FormData: text, cefr_level）
  → 后端处理：
      ├─ 构建 CEFR 感知的纠错 Prompt（含错误类型枚举 + JSON 输出格式）
      ├─ DashScope qwen-plus（temperature=0.3）生成纠错结果
      ├─ 解析 JSON：corrected_text / errors[] / polished_version / suggestions[]
      └─ 返回纠错结果
  → 前端展示：
      ├─ 原文 vs 修正版对比卡片（差异词高亮：红删绿增）
      ├─ 错误列表（类型标签 + 颜色编码 + 原文→修正 + 中文解释）
      ├─ 地道表达建议（润色版本）
      └─ 改进建议（2-4 条）
```

#### 6.2 独立语音纠错

```
用户切换到语音模式
  → VoiceRecorder 录音（3 秒准备 + 最长 30 秒）
  → 录音完成 → 上传音频到 POST /api/grammar/correct/voice
  → 后端处理管线：
      ├─ 保存音频到临时文件
      ├─ ffmpeg 转码为 WAV 16kHz
      ├─ WhisperX ASR 转写 → 文本 transcript
      ├─ 调用 correct_grammar(transcript, cefr_level)
      └─ 返回纠错结果（同文本模式）
  → 前端展示同文本模式
```

#### 6.3 对话内实时纠错

```
用户在 AI 对话中说完一轮（POST /api/conversation/stream/speak）
  → ASR 转写完成后：
      ├─ asyncio.create_task(llm.correct_grammar(user_text, cefr_level))  ← 并行执行
      ├─ 同时 LLM 生成对话回复（不等待纠错完成）
      ├─ SSE 事件流：
      │   ├─ asr 事件 → 显示用户转写文本
      │   ├─ token 事件 → 逐字显示 AI 回复
      │   ├─ grammar 事件 → 显示语法纠错结果（如有错误）
      │   └─ done 事件 → 对话完成
      └─ 纠错结果持久化到 conversation_messages.grammar_check 列
  → 前端展示可折叠语法纠错卡片（错误类型标签 + 中英文解释）
```

#### 6.4 角色扮演内实时纠错

```
同对话内纠错流程，集成在 roleplay.py 的 stream/speak 端点中
  → 纠错结果通过 SSE grammar 事件返回
  → 持久化到 roleplay_messages.grammar_check 列
```

### 二、技术架构

| 层次 | 技术 | 说明 |
|------|------|------|
| 前端页面 | Vue 3 + Element Plus | GrammarView（双模式输入 + 差异高亮 + 错误卡片） |
| 前端组件 | VoiceRecorder | MediaRecorder API 录音，WebM 格式 |
| 前端 API | Axios | `api/grammar.js` — correctGrammar / correctGrammarVoice |
| 后端路由 | FastAPI | `api/grammar.py` — 2 个端点（POST /correct, POST /correct/voice） |
| LLM | DashScope qwen-plus | temperature=0.3，8 种错误类型，CEFR 感知提示 |
| ASR | WhisperX small (int8) | 语音纠错时转写音频 |
| 音频处理 | ffmpeg | WebM → WAV 16kHz 转码 |
| 对话集成 | asyncio.create_task | 与 LLM 回复并行执行，不增加延迟 |
| SSE 事件 | grammar 类型 | 纠错结果通过 SSE 流式返回前端 |
| ORM | SQLAlchemy | conversation_messages.grammar_check / roleplay_messages.grammar_check |
| 校验 | Pydantic | GrammarError / GrammarCorrectResponse |
| 错误类型 | 8 种 | tense / subject_verb_agreement / article / preposition / word_order / plural / word_choice / other |
