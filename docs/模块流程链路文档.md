## 模块 1：用户注册与多维度画像

### 一、功能流程

#### 1.1 注册流程

```
用户打开 /register 页面
  → 填写表单：用户名、邮箱、密码、确认密码、年龄、学习目标、兴趣标签
  → 前端表单验证（正则校验用户名/邮箱/密码格式）
  → 点击「注册并开始测评」
  → 调用 authStore.register()
  → 成功后存 Token 到 localStorage + Pinia
  → 路由跳转到 /assessment（水平测评）
```

#### 1.2 登录流程

```
用户打开 /login 页面
  → 输入用户名 + 密码
  → 点击登录
  → 调用 authStore.login()
  → 后端验证密码 + 检查 is_active
  → 成功后返回 JWT + assessment_completed 状态
  → 前端存 Token，根据 redirect 字段跳转：
      ├─ assessment_completed = false → /assessment
      └─ assessment_completed = true  → /home
```

#### 1.3 个人资料查看与编辑

```
用户打开 /profile 页面
  → onMounted 调用 authStore.fetchProfile() → GET /api/auth/profile
  → 展示只读信息（用户名、邮箱、年龄归类、CEFR 等级）
  → 可编辑字段：学习目标（下拉）、兴趣标签（多选）
  → 点击「保存修改」→ PUT /api/auth/profile
  → 后端乐观锁校验 version 字段，并发安全
```

#### 1.4 Token 自动刷新

```
任意 API 请求返回 401
  → axios 响应拦截器捕获
  → 检查是否已在刷新中（isRefreshing 标志）
  → 若未在刷新：调用 POST /api/auth/token/refresh
  → 后端用当前有效 Token 换取新 Token（24h 有效期）
  → 前端更新 localStorage + 重试原始请求
  → 若刷新失败：清除登录状态，提示重新登录
  → 若已在刷新：请求加入 pendingRequests 队列，等待刷新完成后重试
```

#### 1.5 路由守卫

```
每次路由切换 → router.beforeEach 守卫：
  ├─ 游客路由（/login, /register）+ 已登录 → 重定向 /
  ├─ 需认证路由 + 未登录 → 重定向 /
  ├─ 已完成测评 → 禁止再访问 /assessment → 重定向 /
  ├─ 未完成测评 + 非豁免路径 → 强制跳转 /assessment
  └─ 角色路由（/teacher/*, /admin/*）→ 角色不匹配 → 重定向 /
```

#### 1.6 管理员禁用/恢复账号

```
管理员调用 POST /api/auth/admin/toggle-status
  → 验证当前用户 role == "admin"
  → 不能禁用自己
  → 修改目标用户 is_active 字段
  → 被禁用用户下次请求时 get_current_user 拦截（is_active != 1 → 401）
```

### 二、技术架构

| 层次 | 技术 | 说明 |
|------|------|------|
| 前端页面 | Vue 3 + Element Plus | RegisterView / LoginView / ProfileView |
| 前端状态 | Pinia + localStorage | Token 持久化，userInfo 响应式管理 |
| 前端路由 | Vue Router 4 + beforeEach 守卫 | 5 层权限检查（guest/auth/assessment/role） |
| 前端 HTTP | Axios + 请求/响应拦截器 | 自动附带 Token，401 自动刷新 + 重试队列 |
| 后端路由 | FastAPI | `api/auth.py` — 6 个端点（register/login/profile/update/refresh/toggle） |
| 认证 | JWT (python-jose) | HS256 签名，24h 有效期，无状态 |
| 密码安全 | bcrypt (passlib) | 不可逆哈希 + salt |
| 并发控制 | 乐观锁 | user_profiles.version 字段 + WHERE 条件更新 |
| ORM | SQLAlchemy | `UserProfile` 模型映射 `user_profiles` 表（20+ 字段） |
| 校验 | Pydantic | RegisterRequest/LoginRequest/ProfileUpdateRequest 请求校验 |

## 模块 3：个性化学习路径规划

### 一、功能流程

#### 3.1 每日任务生成

```
用户登录后进入「学习路径」页面
  → onMounted 调用 store.fetchTasks()
  → GET /api/learning-path/tasks
  → 后端检查 daily_tasks 表今日是否已有任务：
      ├─ 有 → 直接返回已有任务
      └─ 无 → 执行六步生成法：
          ① 短板优先 → 从 user_skill_scores / 测评记录取最低分维度
          ② 目标加权 → learning_goal 映射场景偏好（日常/考试/商务/出国/兴趣）
          ③ CEFR 匹配 → 图查找 BELONGS_TO 同等级的技能节点
          ④ 前置依赖 → 检查技能前置链是否满足（HAS_PREREQ）
          ⑤ 兴趣优选 → 资料标签 ∩ 用户兴趣标签
          ⑥ 写入 daily_tasks → 返回 3 个任务（跟读+对话+听力各 1 个）
  → 前端展示任务卡片列表 + 进度条（done/total）
```

#### 3.2 任务操作

```
跳过任务：
  → POST /api/learning-path/tasks/{id}/skip
  → 更新 status="skipped" + skip_reason
  → 返回更新后的任务

换一个：
  → POST /api/learning-path/tasks/{id}/replace
  → 删除旧任务 → 生成同类型新任务（随机选取同 CEFR 等级的技能/场景/资料）
  → 返回新任务

调整难度：
  → POST /api/learning-path/tasks/{id}/adjust-difficulty（direction: easier/harder）
  → CEFR 等级 ±1 级（钳制 A1-C2）
  → 返回更新后的任务

完成任务：
  → POST /api/learning-path/tasks/{id}/complete（score + duration_seconds）
  → 更新 status="completed" + completed_at
  → profile_updater.ingest_task_score() 摄入分数到动态画像
```

#### 3.3 历史记录

```
用户展开「学习历史」区域
  → GET /api/learning-path/history?days=7
  → 后端查询最近 N 天的 daily_tasks
  → 按日期分组：每日的任务状态序列 + 完成数 + 总数 + 学习分钟数
  → 前端展示日历列表（done/skipped/pending 图标 + 统计）
```

#### 3.4 资料推荐

```
用户进入「资料推荐」页面
  → GET /api/recommendations/
  → 后端执行四因子评分推荐：
      ① 短板匹配 (40%) → 资料 TEACHES 的技能是否属于用户短板维度
      ② 难度匹配 (35%) → 资料 CEFR 与用户 level_final 差值
      ③ 兴趣匹配 (25%) → 资料标签 ∩ 用户兴趣标签
      ④ 新颖度（乘性因子）→ 7 天内推荐过打折，disliked 归零
  → 按分数降序，取视频×2 + 文章×2 + 音频×2
  → 写入 material_recommendations 表
  → 返回 6 条推荐资料
```

#### 3.5 资料交互

```
用户点击「不感兴趣」：
  → POST /api/recommendations/{id}/dislike
  → 更新 action="disliked"
  → 后续推荐该资料新颖度归零，不再出现

用户点击资料：
  → POST /api/recommendations/{id}/click（action: view/complete）
  → 更新 action + viewed_at

用户点击「换一批」：
  → POST /api/recommendations/refresh
  → 每日限 3 次手动刷新（首次加载不计入）
  → 超限返回 HTTP 429
  → 重新计算四因子评分 → 写入新推荐记录
```

### 二、技术架构

| 层次 | 技术 | 说明 |
|------|------|------|
| 前端页面 | Vue 3 + Element Plus | LearningPathView（任务卡片） + RecommendationView（资料列表） |
| 前端状态 | Pinia Store | `learning_path.js` — 任务/进度/操作状态管理 |
| 前端路由 | Vue Router | `/learning-path` + `/recommendations` |
| 后端路由 | FastAPI | `api/learning_path.py` — 6 个端点（tasks/skip/replace/adjust/complete/history） |
| 后端路由 | FastAPI | `api/recommendation.py` — 4 个端点（GET //dislike/refresh/click） |
| 知识图谱 | NetworkX DiGraph | 129 节点 + 292 边，启动时从 MySQL 全量加载到内存 |
| 图遍历 | BFS + 拓扑排序 | `get_prerequisite_chain()` 收集前置依赖 → `nx.topological_sort()` |
| 推荐算法 | 四因子评分 | 短板 40% + 难度 35% + 兴趣 25%，乘以新颖度因子 |
| 任务生成 | 六步规则引擎 | 短板→目标→CEFR→前置依赖→兴趣→写入 DB |
| 画像更新 | ProfileUpdater | 任务完成后 EMA 摄入分数到 user_skill_scores |
| ORM | SQLAlchemy | KGNode / KGEdge / DailyTask / MaterialRecommendation / LearningMaterial / MaterialRecord |
| 校验 | Pydantic | TaskItem / DailyTasksResponse / MaterialItem / RecommendationsResponse |
