## 一、架构理念

### 管线化设计（Pipeline Architecture）

每个模型承担单一职责，模型间通过文本中转，环节可独立替换、可观测、可调试。

```
用户语音
    │
    ▼
┌──────────┐    转写文本    ┌──────────────────┐
│ Paraformer │──────────────▶│  deepseek-v4-flash │
│  (ASR)     │               │  (对话/纠错/推荐)   │
└──────────┘                └────────┬─────────┘
     │                               │
     │ 转写文本                      │ AI 回复文本
     ▼                               ▼
┌──────────┐                ┌──────────┐
│  Echoic   │                │ 豆包 TTS  │
│ (发音评分) │                │ (语音合成) │
└──────────┘                └─────┬────┘
     │                            │
     ▼                            ▼
  评分结果                     语音回复播放

┌──────────┐
│  Milvus   │ ← 长期记忆 / 推荐检索（P2上线）
└──────────┘
```

### 为什么不用端到端语音模型

端到端模型（如 Fun-Audio-Chat-8B）是黑盒，存在三个致命问题：

| 问题 | 说明 |
|------|------|
| **评测无据** | 无法从黑盒获取转写文本，语法纠错、流利度评估、对话评分均无数据源 |
| **质量不足** | 8B 参数不足以支撑多轮角色扮演和复杂上下文 |
| **不可替换** | 黑盒模型绑死所有环节，ASR/LLM/TTS 任一环节想升级都做不到 |

## 二、模型清单

| 序号 | 模型/服务 | 厂商 | 许可证 | 承担功能 | 部署方式 |
|:---:|------|------|:---:|------|:---:|
| 1 | **Paraformer** | 阿里达摩院 | 开源 | 语音转文字（ASR） | 自部署（GPU） |
| 2 | **deepseek-v4-flash** | 深度求索 | 商业 API | 对话生成、语法纠错、语义评分、内容推荐、智能客服 | API 调用 |
| 3 | **Echoic** | 开源社区 | MIT | 发音评测（音素级三维评分） | Docker 自部署 |
| 4 | **豆包 TTS** | 字节跳动 | 商业 API | 语音合成（AI 回复 + 标准音播放） | API 调用 |
| 5 | **Milvus** | Zilliz | 开源 | 向量检索（长期记忆 + 个性化推荐） | 自部署（P2 上线） |

## 三、各模型职责详解

### 1. Paraformer — 速记员

| 维度 | 说明 |
|------|------|
| **定位** | 唯一 ASR 入口，所有语音输入统一经 Paraformer 转写为文字 |
| **调用场景** | 模块 2（测评口语题）、模块 4（发音跟读）、模块 6（AI 对话）、模块 8（角色扮演）、模块 16（语音提问） |
| **输出** | 带时间戳的转写文本，供后续所有文本处理链路消费 |
| **部署** | GPU 服务器自部署，数据不出域 |
| **性能要求** | 单次转写 < 1s |

### 2. deepseek-v4-flash — 语文老师

| 维度 | 说明 |
|------|------|
| **定位** | 核心 LLM，承担所有文本生成和语义理解任务 |
| **调用场景** | |
| | — 模块 2：口语题自由表达评分（内容/语法/词汇/连贯性） |
| | — 模块 3：学习路径任务生成 |
| | — 模块 6：对话回复生成 + 难度控制 |
| | — 模块 7：语法纠错 + 地道表达润色 |
| | — 模块 8：角色扮演 Prompt 驱动 |
| | — 模块 9：推荐内容匹配 |
| | — 模块 16：智能客服问答 |
| **性能要求** | 对话回复 < 1.5s，纠错/评分 < 1s |
| **成本** | 1 元/百万 token，单次对话约消耗 3000-5000 token |

### 3. Echoic — 发音教练

| 维度 | 说明 |
|------|------|
| **定位** | 本地部署的音素级发音评测引擎 |
| **仓库** | github.com/xialeistudio/echoic |
| **许可证** | MIT |
| **技术链路** | WhisperX（ASR + 时间对齐）→ wav2vec2（强制对齐）→ phonemizer（音素评分） |
| **评分维度** | 准确度（Accuracy）、流利度（Fluency）、完整度（Completeness） |
| **评分粒度** | 单词级 + 音素级，音素按得分绿/黄/红着色定位 |
| **模型大小** | ~1GB，首次启动下载 |
| **硬件** | CPU 可跑，推荐 GPU 加速 |
| **部署** | `docker compose up` 一键启动，提供 REST API |
| **数据安全** | 音频不出服务器，无需上传第三方 |

**三维评分与五维体系映射**：

| 原五维 | Echoic 覆盖方式 |
|------|------|
| 音素准确度 | ✅ Echoic 音素级评分直接对�� |
| 流利度 | ✅ Echoic Fluency 维度 |
| 完整度 | ✅ Echoic Completeness 维度 |
| 重音位置 | ⚠️ wav2vec2 特征隐式评估 |
| 语调曲线 | ⚠️ wav2vec2 特征隐式评估 |
| 连读表现 | ⚠️ wav2vec2 特征隐式评估 |
| 节奏感 | ⚠️ wav2vec2 特征隐式评估 |

### 4. 豆包 TTS — 播音员

| 维度 | 说明 |
|------|------|
| **定位** | 所有语音输出的统一 TTS 引擎 |
| **调用场景** | 模块 4（标准音播放）、模块 6（AI 对话语音回复）、模块 8（角色扮演语音回复） |
| **优势** | 多音色、有情感，比 Edge TTS 音色丰富 |
| **免费额度** | 火山引擎每月 100 万字符，MVP 阶段够用 |
| **超量价格** | 2 元/百万字符 |

### 5. Milvus — 学习委员的笔记本

| 维度 | 说明 |
|------|------|
| **定位** | 向量数据库，长期记忆 + 语义检索 |
| **上线时间** | P2（P0/P1 阶段用 MySQL JSON 兜底） |
| **调用场景** | |
| | — 用户历史发音错误语义检索（相似错误案例推荐） |
| | — 学习资料语义匹配（相似内容推荐） |
| | — 长期学习记忆（跨 session 上下文） |
| **部署** | 开源自部署，Docker Compose |

## 五、性能指标

| 指标 | 目标 | 说明 |
|------|:---:|------|
| Paraformer 转写延迟 | < 1s | 单次语音→文本 |
| deepseek-v4-flash 对话回复 | < 1.5s | 文本生成 |
| deepseek-v4-flash 语法纠错 | < 1s | 文本纠错 |

| 豆包 TTS 合成 | < 1s | 文字→语音 |

| **对话端到端延迟（优化后）** | **< 3s** | 并行 Pipeline 优化 |
| MVP 并发支持 | 500+ 用户 | |

## 六、技术风险与应对

| 风险 | 应对 |
|------|------|
| Echoic 本地推理延迟高 | 评估异步返回；GPU 加速；可降级为简版评分 |
| deepseek-v4-flash 不稳定 | 超时降级预设回复；前端骨架屏 + 自动重试 |
| 豆包 TTS 合成失败 | 仅展示文字回复，标注「语音暂不可用」 |
| 端到端延迟 > 5s | 流式 TTS 首块音频先播；Paraformer 和 deepseek-v4-flash 并行执行 |
| 多年龄发音泛化差 | 初期聚焦 15-40 岁；儿童/老人用宽松阈值 |
| 自部署模型运维 | Paraformer + Echoic + Milvus 全部容器化，统一 Docker Compose 管理 |
